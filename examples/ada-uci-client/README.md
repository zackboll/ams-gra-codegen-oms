# Standalone receive-only Ada UCI client

This application compiles the production-generated Ada models, codecs and
Subscriber APIs for exactly `LogMT`, `RDMA_InitializeSetupMT` and
`SurvivabilityRiskLevelMT`. One verified WSS connection carries all three
subscriptions. It is independent of the qualification harness at runtime.

**Current safety limitation:** recovery is deliberately limited to unambiguous
peer closure. The production transport combines I/O failures, WebSocket protocol
violations and unexpected exceptions into `Transport_Error`; those exceptions
remain terminal. R1 incorporates PR204's caller-deadline transport: each fresh
WebSocket receives the same global absolute deadline before Open. Setup, writes,
queued controls and cleanup are bounded without resetting time on recovery.
Broader abrupt-network recovery still requires separate structured transport
classification work; full TASK115 acceptance is **not** claimed.
See `/docs/task-115-ada-uci-standalone-reconnect.md`.

## Prerequisites and authentic inputs

Build from a complete checkout. Supply GNAT 14.2.0 or 16.1.0, GPRbuild 26,
GNATCOLL 26, and the pinned AHT/websocket-ada source. Existing TASK110 isolated
Alire setups are supported: `SETUP` has `settings`, `home`, and `consumer` with
an already solved `alire.lock` and cached GNATCOLL dependencies. The helper uses
`alr printenv` and copies provider sources into external scratch; it does not
upgrade dependencies or install compilers.

`DEPS` contains clean Git checkouts named `aht`, `codec` (websocket-ada),
`sleet`, `uci25`, `uci26` at these authorities:

| Source | Commit |
| --- | --- |
| AHT | `827b0c17dd964e935f8e88912ce0611ee92b6f16` |
| websocket-ada | `765d9cd612838eb00645037977c8cc9af7171c3e` |
| Sleet | `e38f61d8ce0d75c8508434a52f2ed77c69cf6a3b` |
| UCI 2.5 | `093610b7753944059360d3236770ab446d039556` |
| UCI 2.6 | `78eb61b6112c8bffa40820c33124b57787fc5bd9` |

`SCHEMA` is the directory containing the authentic selected-release message and
security XSDs. For 2.6, extract the pinned archive externally. Both authoritative
XSD SHA-256 hashes are verified before generation. No schemas, generated UCI
source, TLS keys or binaries belong in this directory or Git.

## Independent build

From the repository root (replace variables with absolute paths):

```sh
cargo build --release --locked -p ams-gra-codegen-oms
python3 scripts/task115/build.py \
  --release 26 --compiler 16 --backend openssl \
  --setup "$SETUP" --deps "$DEPS" --schema "$SCHEMA" \
  --generator "$PWD/target/release/ams-gra-codegen-oms" \
  --scratch "$CLIENT_SCRATCH"
"$CLIENT_SCRATCH/build/bin/ada-uci-client" --help
```

Choose `--release 25` with its authentic schema directory to build UCI 2.5.
Each scratch directory must be new and outside the repository. To select
mbedTLS use `--backend mbedtls`; the pinned AHT checkout must already contain
its existing `third_party/mbedtls-3.6.7` provider. Each build uses isolated object
and provider directories, preventing compiler/backend cache mixing.

The helper runs unchanged production `service-check`, then `service-generate
--language ada --world closed-schema --with-codec`. It writes the selected OWP
schema into `uci_client-build_config.ads` in scratch, generates a GPR project,
and invokes GNAT/GPRbuild with Ada 2022, assertions and overflow checking.
`build.json` records source/tree, input hashes, generated hashes, schema hashes,
dependency identities, compiler, backend and executable hash. Command JSON and
stdout/stderr stay in scratch. The client has no runtime schema override.

## Run against an authorized Sleet endpoint

Configure Sleet's service registry with identity `ada-uci-client` and authorize
`uci.log`, `uci.rdma`, `uci.survivability`. Use the same schema release as the
executable. The message global names are `Log`, `RDMA_InitializeSetup`, and
`SurvivabilityRiskLevel`. No publication endpoint is generated by these contracts.

```sh
"$CLIENT_SCRATCH/build/bin/ada-uci-client" \
  --url wss://localhost:9443/ --ca-path /absolute/path/to/ca.pem \
  --duration-seconds 30

# Explicit opt-in: at most two additional sessions across the entire process.
"$CLIENT_SCRATCH/build/bin/ada-uci-client" \
  --url wss://localhost:9443/ --ca-pem-file /absolute/path/to/ca.pem \
  --duration-seconds 30 --reconnect-attempts 2 --reconnect-delay-ms 250
```

`--ca-pem-file` reads PEM contents into `CA_PEM`; it is mutually exclusive with
`--ca-path`. Trust configuration is mandatory; certificate and original-hostname
verification are always enabled. There is no plaintext or insecure fallback.
An explicit port is required by the existing transport. IPv6 URL literals are
not supported. Duration is 1–3600 seconds, reconnect attempts 0–8 (default 0),
delay 50–2000 ms (default 250). Unknown, duplicate, conflicting, malformed and
out-of-range arguments are rejected before `CONNECTING`. `--help` stands alone.
Exit status is 0 on duration completion, 1 on session/application failure, and 2
on invalid arguments.

Duration expiry is successful only in a fully established current epoch. Initial
or replacement setup expiry and expiry while disconnected in a recovery delay
exit 1. Transport/setup failures remain failures even when the deadline has passed.
Close releases abortively rather than waiting after the global deadline expires.

Output shows compiled schema, epoch, acknowledged subscriptions and selected
generated fields (timestamps, severity, setup/risk UUIDs and collection counts).
It does not print arbitrary Log details/data or security marking structures.
Generated decoding enforces checked model representations; the application
checks each callback's schema identity before reporting it.

## Lifecycle and failure policy

Each invocation of `Epoch` owns its transport, connection, receivers, three
typed bindings, borrowed dispatcher list, SIDs and event counters. Automatic
finalization finishes before the supervisor starts another epoch. The application
uses `OMS_LACAL.Dispatchers.Poll_And_Dispatch`, not a handwritten JSON decoder.
All events are drained and lost-event growth is terminal. OWP errors, generated
decoder errors, handler errors and unexpected exceptions are terminal. Initial
failures are fail-fast even when recovery is enabled. A successful session
requires verified upgrade, one INIT ACK plus valid INFO, and three SUB ACKs.

Recovery consumes one process-wide attempt, waits only until the shared monotonic
deadline or configured delay, and creates fresh lexical state. Successful recovery
never replenishes the budget. Ambiguous connection/setup errors remain terminal;
replacement failures are not retried using backend-specific string matching.
Normal duration shutdown never starts a replacement. Linux procfs counts are
reported after the epoch has finalized, without creating application workers.

There is no PUB, offline queue, publication replay, message resume, lossless
delivery, exactly-once guarantee or durable replay. Disconnected messages are lost.

## Tests and real interoperability

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts/task115 -v
PYTHONDONTWRITEBYTECODE=1 python3 scripts/task115/test_qualification.py --build "$CLIENT_SCRATCH"
# Use a Python environment containing the existing websockets sync client.
python3 scripts/task115/qualify.py --build "$CLIENT_SCRATCH" \
  --evidence "$WSS_SCRATCH" --deps "$DEPS" --release 26
python3 scripts/task115/verify.py "$WSS_SCRATCH" --receipt "$RECEIPT"
```

The test runner executes this executable with its real CLI, an unchanged pinned
Sleet server, and the existing TLS MemoryBIO relay infrastructure. Independent
publisher deliveries, raw WebSocket wire streams, broker registration logs and
typed epoch timestamps are cross-checked. Harness timeouts fail qualification.
Full logs and private keys remain external; compact receipts are separate from
claims of complete TASK115 compliance.
