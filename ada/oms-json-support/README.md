# Qualified Ada JSON support (Task 087A)

`AMS_GRA_OMS_JSON_Guard` provides guarded `Read` and `Write` operations over
`GNATCOLL.JSON.JSON_Value`. This support project is an application dependency;
the Rust generator does not load, link, or require GNATCOLL.

The manifest requires **GNATCOLL and GNATCOLL minimal 26.0.0**. The qualified
upstream `v26.0.0` tag resolves to
`8e270f83719d4284782a965edd80246be15b949b`. Task 086 records the Alire archive
SHA-512 and its byte comparison with that revision. No provider patch is used.
The support sources use the repository's MIT license. GNATCOLL is licensed
`GPL-3.0-or-later WITH GCC-exception-3.1`; consumers must account for that
dependency's license independently.

GNATCOLL distributes `COPYING3` and `COPYING.RUNTIME`. The latter is the GCC
Runtime Library Exception **3.1**: its additional permission covers eligible
compiled target code combining the library with independent modules; it does
not replace the GPL requirements for distributing the library sources or
modifications. Retain the applicable notices and license texts when
redistributing the dependency. See the provider's full texts, not just the
SPDX identifier, when assessing a particular distribution.

## Consumer setup

Task 095's explicitly target-qualified Float32 codecs use the separate
`ams_gra_oms_json_float32.gpr` project. The ordinary project and guard are
unchanged. See `docs/task-095-ada-float32-codec.md` for the Linux/x86-64 glibc
2.41 runtime opt-in, deployment checks and additional C/libc boundary.
The supported floating environment requires nearest rounding with MXCSR DAZ
and FTZ disabled. Unsupported controls raise `Unsupported_Platform`; production
code never changes the caller's rounding, MXCSR controls or exception masks.

Add to an application's Alire manifest (adjust the local path):

```toml
[[depends-on]]
ams_gra_oms_json = "=0.1.0-dev"

[[pins]]
ams_gra_oms_json = { path = "/absolute/path/to/ada/oms-json-support" }
```

Add `with "ams_gra_oms_json";` to its GPR file and
`with AMS_GRA_OMS_JSON_Guard;` to its Ada sources. Build using `alr -n build`.
Alternatively, make this project and the qualified provider projects available
on `GPR_PROJECT_PATH` and use `gprbuild` directly. This is a reusable source
project, not a precompiled binary library. Object files belong in a task-owned
scratch copy, not in the source checkout.

Ada 2022 is required. Qualification targets GNAT 14.2.0 and 16.1.0; no compiler
is forced by the support manifest. The standalone probe selects GNAT 14.2.0
explicitly, with GNAT 16.1.0 selected in a separate scratch consumer.

## Executable qualification and clean consumer

From the repository root, with Python 3.11+ and Alire **2.1.1** on `PATH`:

```sh
python3 scripts/test-task087a-wrapper.py
python3 scripts/check-task087a.py --compiler 16 --scratch /tmp/task087a-new16
python3 scripts/check-task087a.py --compiler 14 --scratch /tmp/task087a-new14
```

Each scratch path must not already exist. The wrapper copies the project tree
to scratch (preserving the source checkout), selects the exact compiler and
**gprbuild Alire release 26.0.1** (binary reports **GPRBUILD 26.0.0**), validates
the resolved provider archive hash, builds a separate consumer using only a
path dependency on the support crate, and executes the original 199-case
corpus plus four size/depth checks under normal, Check and Ignore policies.
Missing tools, failed builds, nonzero exits, missing markers, changed frozen
evidence, wrong versions and skipped qualification all fail the command.
GNAT 14 uses Alire's explicit force-selection option only to override its
external-compiler/GPRBUILD compatibility heuristic; compilation and execution
remain mandatory. Hosted CI uses the native GNAT 16.1.0 selection without that
override. No global toolchain selection is changed.
Run campaigns sequentially when they share an Alire cache: forced provider
rebuilds must not concurrently write the same cached archives. Hosted CI runs
one campaign in its isolated job.

For an independent library-only build, copy this directory into new scratch,
then run there:

```sh
alr -n toolchain --select --local gnat_native=16.1.0 gprbuild=26.0.1
alr -n build
```

The clean consumer's complete executable source is generated by the wrapper
in `<scratch>/consumer`: it imports `AMS_GRA_OMS_JSON_Guard`, guarded-reads `{}`,
guarded-writes it, checks the exact result and prints a mandatory completion
marker. It imports no Rust artifact and copies no support Ada source into its
own source directory. The existing probe's `JSON_Guard` is solely a package
renaming of the production package.

## Contract and limitations

* Incoming documents are limited to **1,048,576 bytes**, measured before the
  UTF-8 scanner or provider reader runs. Caller-owned input allocation is not
  bounded by this package.
* Before DOM construction, an iterative scanner rejects more than **128**
  simultaneous object/array openings outside strings. It does not check JSON
  grammar or matching delimiter kinds: GNATCOLL remains authoritative.
* Tree traversal rejects depth greater than 128 or more than **100,000** nodes.
  These limits are not a claim of complete memory-resource containment.
* UTF-8 and surrogate escapes are validated without normalization. Every
  outgoing string and key is checked before serialization; serialized lexical
  encoding is checked afterwards. Concurrent DOM mutation is unsupported.
* Duplicates retain GNATCOLL's **last-value-wins**, including escaped equivalent
  keys. This is not a strict duplicate-key receiver policy.
* Integer tokens retain signed 64-bit precision. Overflow is a provider parsing
  error, never a floating fallback. Integer `-0` normalizes to value zero.
  Fraction/exponent tokens are not evidence of integer or Decimal support.
* Returned parser failures and explicit guard rejections raise
  `Validation_Error`. Unexpected `Constraint_Error` is deliberately **not**
  translated: an indexing or programming defect must remain distinguishable.
  No production caller may bypass this boundary for document read/write.

Task 087A delivers the reusable JSON support boundary only. The mandatory
`ada-json-guard` Fast CI job executes the same qualification command using a
SHA-256-verified Alire release archive and the native GNAT 16.1.0 provider
environment. Actual hosted results are separate from local evidence.

Production Ada OMS JSON codec generation and real-UCI codec inventory remain
unimplemented. No `service_codec.ads` or `.adb` is emitted and Ada OMS codec
readiness remains NOT READY. Task 087B will consume this independently reviewed
boundary. This library is not complete OMS JSON conformance or a CAL runtime.
