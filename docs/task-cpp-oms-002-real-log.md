# CPP-OMS-002 — Generated C++17 OMS JSON codec for the authentic UCI `Log`

Builds on CPP-OMS-001 (PR #164, merged to `main` as `c8bb8a5`; this work started
from its head `d7eda351…` and was reconciled with `main` by merge). Production
`service-check --language cpp --world closed-schema --with-codec` and
`service-generate … --with-codec` now report **READY** and emit a compiling
`service_codec.hpp` for the authentic pinned UCI `Log` message in **both** UCI
2.5 and UCI 2.6. Everything outside the exact profiles `Log` needs stays
explicitly NOT READY.

## What was added

The shared readiness analyzer (`codegen-core`,
`cpp_emission_codec_support`) and the C++ renderer (`backend-cpp`,
`service_codec.rs`, `codec_runtime.hpp`) gained exactly these value kinds. The
renderer still calls the analyzer first, so `service-check` and
`service-generate` cannot disagree.

| Construct | Admitted when | Wire form | Authority |
| --- | --- | --- | --- |
| Named String, UUID / UCI schema-version / visible-ASCII / whitespace-visible / NATO special-words profile | `string_profile` classifies one of those five | JSON string | decode → the model's `T::create(std::string_view)`; encode → stored `value()` |
| Named `DateTimeZulu`, named `Duration` | `temporal_profile` is `DateTimeZulu` / `Duration` | JSON string (XML lexical form) | `T::create` / `value()` |
| Direct `xs:dateTime`, direct `xs:duration` member | no field facets | JSON string | `XmlSchemaDateTime` / `XmlSchemaDuration` `create` / `value()` |
| `xs:hexBinary`, direct member or unconstrained named declaration | IR lexical provenance is `HexBinary`, no length facet | JSON string | codec lexical mapping; the model carrier is `std::vector<std::uint8_t>` / `HexBinaryType` |
| Choice declaration | every alternative is a required single (`1..1`) | object with exactly one member, the alternative's own element QName | each alternative decoded with its own type; the model's `std::variant` wrapper is selected by name |

Behavioral details (all independently expected in the consumers, none produced
by the encoder under test):

* **Strings keep the model's semantics, including its release differences.**
  `WhitespaceVisibleString*` collapses XML whitespace in UCI 2.5 (`"  a \t b\n"`
  is stored and written as `"a b"`, empty allowed) but in UCI 2.6 is
  `whiteSpace=preserve` with `minLength 1` and rejects TAB (`"a\n b"` is
  stored unchanged and written `"a\n b"`). `DeclassDate` is a direct
  `xs:dateTime` in 2.5 (an offset such as `-05:00` is valid) and the Zulu-only
  `DateTimeType` in 2.6 (the same offset is rejected). Both are asserted per
  release; neither was loosened to make the releases agree.
* **Duration / DateTime lexical form is preserved**, not canonicalised
  (`"PT01.2300S"` stays `"PT01.2300S"`); XML `whiteSpace=collapse` is applied on
  the way in by the model's `create`.
* **hexBinary** decodes case-insensitively after XML whitespace collapse
  (leading/trailing whitespace tolerated, internal whitespace rejected) and
  always encodes canonical uppercase. An empty value is a present, empty
  binary; absence is `std::nullopt`. This is the same mapping as the Rust
  codec (`decode_hex_binary`), and Sleet's weaker lexical check is not mirrored.
* **Choice**: encode writes exactly the selected alternative; decode requires
  exactly one non-`$type` member, rejects zero, several, unknown names, wrong
  JSON kinds and duplicates, and names the alternative in the error path
  (`LogMT.SecurityInformation.OwnerProducer[1].NATO_SpecialWord`). A matching
  `$type` is tolerated and never emitted. A reserved-word alternative keeps its
  model identifier but its exact wire name (`begin` → `Selection::Begin`).
* Wire names, namespaces, flattened inheritance, optionality, repetition and
  error paths are unchanged from CPP-OMS-001.

## Qualification evidence

### Authentic Log, both releases

`scripts/check-cpp-oms-002-real-log.sh` obtains the pinned roots through the
existing `scripts/fetch-pinned-uci-2.{5,6}.sh` (tag → commit and root SHA-256
verified), additionally verifies the imported `UCI_SecurityMarkings_v2_{5,6}_0.xsd`
hashes (cross-checked against the pins in `scripts/task102/admission.py`), then
for each release:

1. runs production `service-check … --with-codec` and requires the exact lines
   `selected type closure: 42|44`, `renderable selected types`, `status: READY`,
   `codec renderable emitted declarations: 41/41|43/43`, `codec status: READY`;
2. runs production `service-generate` with and without `--with-codec` and
   requires `oam.hpp` and `service_api.hpp` to be byte-identical;
3. compiles `tests/cpp-codec/log_consumer.cpp` with strict flags
   (`-std=c++17 -Wall -Wextra -Wpedantic -Werror -Wconversion -Wsign-conversion
   -Wshadow -Wold-style-cast -Wcast-align -Wnon-virtual-dtor
   -Woverloaded-virtual -Wnull-dereference -Wdouble-promotion -Wformat=2`) with
   g++ and clang++, and with ASan+UBSan where a sanitizer runtime is usable, and
   runs it on the existing Task 093 golden (`task093-real-log25.json` /
   `task093-real-log26.json`), requiring the exact summary
   `checks=307 rejections=189` (2.5) / `checks=307 rejections=192` (2.6) for
   every compiler and sanitizer build, not merely a positive count.

`log_consumer.cpp` (307 checks per release; 189 rejections in 2.5, 192 in 2.6):

* decodes the golden and inspects classification, both `OwnerProducer` Choice
  alternatives (a government identifier and a `NATO_SpecialWord`), the UUID,
  header and data timestamps, schema version, mode, the preserved duration
  text, severity, label, details and the three octets `00 80 FF`;
* re-encodes to a **hand-written** compact document in schema order, and
  round-trips further hand-written documents: Data absent / empty / populated
  (`DEADBEEF000A`) / lowercase / whitespace-padded input; ServiceUpTime
  absent / negative / padded; `ServiceID`, repeated `ComponentID`; `Joint`,
  repeated `SCI_Controls` (wire value `BUR_BLG`), repeated `ReleasableTo`
  Choices, `ClassifiedBy`, `DeclassDate`; member order irrelevance;
* rejects with a checked path **and** message fragment: malformed UUIDs (length,
  hyphens, non-hex, version 6, variant `c`, braces, leading space, empty,
  non-string), invalid DateTime (month 13, 30 February, hour 24, minute 60, no
  zone, offset where Zulu is required, wrong separators, empty, number),
  invalid Duration (`P`, `PT`, `1H`, `PT1.S`, lowercase, trailing `T`, number,
  array), invalid Choice values (empty object, two members, unknown member,
  wrong kinds, `null`, unknown/lowercase enum, `NATO:` prefix problems, wrong
  `$type`), malformed hexBinary (odd, bad digit, internal whitespace, `0x`,
  non-ASCII, escaped NUL, number/array/bool/null, base64 text), duplicate
  members (top level, nested, after `\u` unescaping, inside an unknown member),
  invalid cardinality (`OwnerProducer` empty, missing and non-array,
  `SCI_Controls` 21 > 20 and the accepted 20), every required member missing,
  unknown members, the global-element envelope, constrained-String violations
  (empty / control / non-ASCII / DEL / NUL / over-length labels, malformed
  schema versions), JSON syntax (BOM, trailing content or comma, lone surrogate,
  raw control character), every 7th truncation prefix, and every single-byte
  corruption (must not crash);
* was shown to bite: deliberately broken copies of the generated codec (odd
  hexBinary accepted, lowercase hex output, several Choice members accepted,
  duplicate members allowed, `create` skipped, wrong Choice key) each fail it.

## Compatibility boundary

READY (for the C++ codec) now means a payload whose selected closure uses only:
Boolean; integral (including bounded/patterned); plain `xs:string` members;
enumerations; the five named String profiles above; named `DateTimeZulu` and
`Duration`; direct unconstrained `xs:dateTime` / `xs:duration`; unconstrained
`xs:hexBinary`; required-single Choices; and concrete Records of those with
required, optional and repeated members.

Still NOT READY, each with a `service codec boundary:` line and no output:

* `xs:float` / `xs:double` (named or direct) — this is now the first blocker for
  most real messages: `PositionReport` (50/59 declarations) and `AMTI_Command`
  (191/217 in 2.5, 192/218 in 2.6) stop at `AccelerationType` (named Float64);
* named `Time` (`TimeZulu`) and any DateTime/Duration with unsupported facets;
* the other String profiles: bounded ASCII (`AO_CapabilityStatus` stops at
  `AO_PIM_CodeType`), structured ASCII, alternating ASCII, IPv6, Unicode 3.1,
  and unconstrained named Strings;
* length-constrained named Binary (`length`/`minLength`/`maxLength`) and
  `base64Binary` or unknown binary provenance;
* Choice alternatives that are optional or repeated;
* abstract structural values / `$type` polymorphism, uninhabited abstract
  members, nillable and unqualified members, aliases and lists;
* anything the C++ **model** itself cannot render.

Not claimed: any transport, LA-CAL/Sleet runtime or OWP framing for C++ (the
codec handles the payload body only, never the global-element envelope); XML
1.0 `Char` restrictions on plain strings; any message other than `Log`.

## Reproduce

```sh
# authentic Log, both releases (fetches the pinned roots outside the repo)
scripts/check-cpp-oms-002-real-log.sh

# or with existing checkouts
AMS_GRA_UCI_2_5_ROOT=… AMS_GRA_UCI_2_6_ROOT=… scripts/check-cpp-oms-002-real-log.sh

# registered tests (synthetic shapes, golden, unsupported constructs)
cargo test --locked -p ams-gra-codegen-oms --test cpp_codec --test service_codec

# re-bless the synthetic golden after an intentional generator change
CPP_OMS_001_BLESS=1 cargo test --locked -p ams-gra-codegen-oms --test cpp_codec
```

Sanitizers run where supported and are never reported as a pass when they
cannot run: the script prints each skipped combination as `SKIPPED (not
claimed as a pass)` and exits 3 if no sanitizer ran or clang++ is missing
(opt out explicitly with `CPP_OMS_ALLOW_SANITIZER_SKIP=1` /
`CPP_OMS_ALLOW_CLANG_SKIP=1`); the registered sanitizer tests fail unless
`CPP_OMS_ALLOW_SANITIZER_SKIP=1` is set. In the container used for this
change, g++ 13.3 ASan+UBSan ran for both releases, while clang++ 18.1.3
sanitizers could not link (no `libclang_rt.asan` runtime installed), so clang++
sanitizer coverage is **not** claimed.

## CI

The existing single-job `PR smoke` C++ step (`python3 scripts/pr_smoke.py run
cpp`, CPP-OMS-002R1) now also runs an **offline** CPP-OMS-002 regression after
the CPP-OMS-001 consumer. For each existing synthetic fixture it generates the
model, service API and codec through the production CLI, compiles
`tests/cpp-codec/shapes_consumer.cpp` with the strict g++ flags and runs it, and
requires the exact deterministic summary line:

| Fixture | Shape | Exercises | Required summary |
| --- | --- | --- | --- |
| `codec-hexbinary` | `HEX` | direct/optional/bounded/unbounded/named hexBinary, hexBinary Choice alternative | `checks=23 rejections=8` |
| `codec-ada-repeated-temporal` | `TEMPORAL` | repeated direct/named dateTime and duration | `checks=15 rejections=6` |
| `codec-ada-choice` | `CHOICE` | Choice incl. reserved-word member, nested Choice, Choice payload | `checks=36 rejections=13` |

A failing or non-reporting shape binary, a compile error, a missing generated
file or any other count fails the job. No UCI schema is fetched; clang++ and
sanitizers stay in the full `cpp_codec` suite. Routing treats
`scripts/check-cpp-oms-002-real-log.sh` as C++-owned. The authentic-UCI script
needs the network pin fetch and is not wired into any workflow (no new runner,
job or workflow was added).
