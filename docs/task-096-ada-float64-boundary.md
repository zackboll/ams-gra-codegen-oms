## Architecture review: source observations, not experimental results

Reviewed production files are `crates/codegen-core/src/{floating,service_codec}.rs`,
`crates/backend-ada/src/{lib,service_codec}.rs`, the entire Float32 support path,
guard source, Float32 probe/runner/environment mechanisms, Task 086/095 reports,
and Task 033's actual report in **`docs/backend-compatibility.md`**, section
"Constrained floating-point ranges (Task 033)" (there is no standalone report
under the suggested filename).

* Pinned GNATCOLL SAX `Parse_Number` identifies original token First/Last without
  converting it. INTEGER_VALUE is integer-form syntax, not a signed-64 promise.
  `GNATCOLL.Buffer.Token` retrieves the original bytes for that occurrence.
* Pinned DOM `Read` uses `Long_Long_Integer'Value` for integer-form input (around
  lines 605–621) and `Long_Float'Value` for NUMBER_VALUE (623–625). The former
  rejects integers outside signed-64; it cannot carry an integer negative zero.
* Pinned `Write` (773–782) uses `Item.Data.Flt_Value'Img`, strips a leading
  space, and appends the image. Its public writer controls only compactness;
  there is no inspected precision or raw-number extension point. On these
  compilers that image has **15 significant decimal digits**, as measured below.
* Merged Float32 occurrences store tagged nodes with original numeric payloads
  as **strings**, kind and positions, decoded object keys, and array positions.
  Last decoded-key occurrence replaces its complete subtree. A same-length
  numeric shadow goes through the existing Unicode/size/depth/node guard,
  while original SAX grammar and occurrences remain authoritative. No numbers
  are matched by name alone or by an unchecked flattened ordinal.
* Float32 rejects unsupported platform/control settings per call, before numeric
  work. Exception categories are `Validation_Error`, `Unsupported_Platform`,
  and `Resource_Error`; impossible bridge status is `Program_Error`. ERANGE
  alone does not reject valid rounded subnormal/zero underflow.
* The shared `floating_domain` API classifies existing inclusive/exclusive,
  width-correct finite named bounds. The model uses `Interfaces.IEEE_Float_64`;
  unconstrained names derive from it. Constrained names are private checked
  carriers with public overloaded `Model.Create` / `Model.Value`. Their own
  `Assertion_Policy (Dynamic_Predicate => Check)` prevents client Ignore from
  bypassing predicates. The research does not reimplement facets.
* The current renderer has an explicit decoder context for occurrence versus
  DOM APIs, but **encoders always use DOM**. A production continuation needs
  width-specific lexeme access and an emitter context as well as a decoder
  context. Simply admitting Float64 in readiness is unsound.

The inspected local `libc6-dev=2.41-12+deb13u4` header declares
`double strtod_l(const char *restrict, char **restrict, locale_t)`.
The actual libc exports `strtod_l@@GLIBC_2.3`, `newlocale@@GLIBC_2.3`,
`uselocale@@GLIBC_2.3`, and `snprintf@@GLIBC_2.2.5`. Research imports use C
`double`, Ada `Interfaces.C.double`, explicit length/capacity, consumed length,
and diagnostic errno. This is a glibc interface, not portable ISO C `strtod`.

## Independent oracle and frozen corpora

`oracle.py` uses only integer/Fraction arithmetic for expectations. It parses
JSON decimal grammar, bounds token work to 16,384 bytes, classifies obvious
huge exponents **before** allocating powers of ten, derives the binary exponent
by integer comparisons, and divides at the appropriate normal/subnormal lattice
spacing. Quotient remainder comparison implements nearest/ties-even; a carry
renormalizes, overflow ties round toward the even next exponent, and zero keeps
the original sign. Leading-zero exponent length is not mistaken for magnitude;
long mantissas may compensate moderate exponents.

The independently implemented reference searches ordered finite encodings and
compares exact rational distances. Its full-corpus review checks **27,162**
non-short-circuited rational rows with zero disagreements; huge-exponent/zero
short circuits have explicit tests. Rust direct f64 parsing independently
cross-checks all **27,167** rows, also zero disagreements. Rust parsing is not
the oracle. No Python float, libc conversion, Ada `'Value`, provider, or
candidate formatter supplies expected bits. Seven unit tests cover known bits,
even/odd ties, overflow midpoint, compensation, invalid syntax, resource bounds,
independent search and evidence-accounting defects. A later strict token-identity
accounting test brings the final unit suite to eight tests; the initial clean
orchestrator's unit log retains the earlier seven-test count rather than being
rewritten.

## Complete handwritten prototype

`Task096_Adapter` is a narrow shape-specific adapter, **not** a new general JSON
parser or general serializer. The generated model/API files remain unmodified.
The production occurrence reader is copied unchanged into each scratch build;
a **research-only child package** exposes a numeric node's original string
payload to the Float64 helper without adding a production API. Float32 still
uses the existing occurrence helper. Existing parser/guard rules remain in
force: UTF-8, surrogate and escaping checks, 1,048,576-byte document limit,
depth 128 and 100,000 nodes, including duplicate occurrences.

Decoder access follows structural nodes, decoded keys and checked array
indices. Whole-subtree replacement is inherited from the inspected occurrence
implementation. Checked named values use generated `Model.Create` / `Value`.
Construction happens in a temporary model; the caller receives it only after
complete validation. The adapter translates expected malformed/range errors,
not every internal exception.

Output is authored from the typed model in a fixed traversal: each Float64
position receives its own formatter result immediately. Existing provider
escaping/writing handles keys, strings, Boolean/integer and Float32 leaves.
There are **no untrusted output placeholders, string search/replacement,
numeric ordinal correlation, numeric DOM reinsertion, or final DOM rewrite**.
The final document passes the original occurrence/guard reader for validation
only, and is not serialized again. Fixture-construction placeholders in the
Python test are not part of this output design.

Both compilers × both namespace profiles × three policies pass:

* 7 accepted structural variants: full payload, reversed member order, escaped
  key, escaped-equivalent duplicate, whole-subtree replacement, optional absent,
  and exact optional special string;
* 17 semantic/syntax/Unicode/resource rejections, all with unchanged published
  model: numeric overflow, quoted number, hex, plus, leading zero, malformed
  document, trailing value, wrong case special, named range failure, missing
  member, wrong Boolean, replaced subtree losing required member, indexed array
  errors at positions 1 and 2, malformed surrogate, depth and byte limits;
* invalid output string rejection leaves the existing output string unchanged;
* exact `NaN`, `Infinity`, `-Infinity` document output semantics (not payload or
  signaling-state preservation);
* actual German thread-locale full-document execution and exact restoration;
* **20,474 complete documents per cell**, eight independently attributed typed
  Float64 positions per document, checked by exact-rational token rounding.

That is 245,688 full-corpus documents / 1,965,504 numerical position checks
across twelve cells, not 1,965,504 unique patterns. All constrained/repeated,
nested and Choice-of-Record fields compose in the structural fixtures.
The adapter's order and non-Float64 leaves are deterministic; no claim is made
that its handwritten order is a newly generated codec artifact. Existing
Float32-only and portable production output remains byte-for-byte untouched.
This shape-specific decoder does not implement the generated renderer's
exhaustive unknown-member allowlist. Unknown-member policy is therefore an
explicit production integration test, not a claimed compatibility result of
this adapter; malformed known values and structural associations are tested.

## Floating environment, locale and failure atomicity

The C predicate follows the merged inspected contract: x87 `fegetround` nearest,
MXCSR RC bits 13–14 nearest, DAZ bit 6 off, FTZ bit 15 off, runtime/ABI attributes
verified. It is called on every operation, not cached. Ada public-style entry
points call it before parsing, classification, widening/narrowing or output.
Test-only controls reuse the existing Task 095 raw x87/MXCSR harness, not a
new interpretation of FE encodings.

All sixteen independent x87/MXCSR pairs cross all four independent DAZ/FTZ
states. Only nearest/nearest with neither flushing bit is supported. Unsupported
calls reject before work and retain integer/byte-checked output sentinels.
Controls are measured before diagnostic logging; supported conversions may set
normal sticky exception flags, which production does not promise to preserve.
Test harnesses restore full fenv/MXCSR including status, verify exact restoration,
then demonstrate a successful call; controls are restored on exception paths.

* C O0/O2: **128 isolated executions**, 37 checks in the supported configuration,
  68 otherwise.
* Ada both compilers/profiles/policies: **768 isolated executions**, 17 checks
  in the supported configuration and 19 / 5 expected rejections otherwise,
  with call/publication/restoration controls.
* C resource injection O0/O2: 81 checks each, including failed locale allocation,
  failed initial locale switch, capacities, embedded NUL, invalid/special C input,
  unchanged outputs and successful recovery.

The formatter retains no locale approval/cache. A restore failure is classified
as resource failure before output; an impossible failed restoration cannot be
advertised as successful restoration. Real previous-handle restoration is
executed for both global-locale sentinel and installed thread locales. Production
continuation should retain fault injection and review this lifecycle explicitly.

## Smallest production continuation (not implemented here)

1. **Capability/version:** retain the current Float32 profile's semantics and
   output unchanged. Prefer an explicitly versioned lossless-float emission
   capability/profile until the new emitter is production-qualified. The same
   target/environment predicate can admit both widths only after ABI, deployment
   and hosted qualification; a Linux generator host is not target approval.
2. **ABI:** keep explicit C double/Ada C.double/IEEE_Float_64 width/radix/exponent,
   signed-zero and exchange checks on the deployment runtime. Prohibit fast-math,
   record libc package/binary identity, link glibc/m, and fail unsupported targets.
3. **Ingress:** expose width-neutral original-lexeme access on authoritative
   occurrence nodes; dispatch to width-specific direct `strtof_l` / `strtod_l`,
   never through DOM, integer-only storage, or Float32 `'Value`. Validate JSON
   syntax separately; keep finite ERANGE underflow and reject infinity overflow.
4. **Output:** introduce a narrow structural emitter context with typed numeric
   leaf methods and existing provider escaping/guards for nonnumeric leaves.
   A Float64 method writes a bounded lossless decimal directly to its position;
   no later DOM serialization may touch it. Review buffer/resource lifecycles.
5. **Models:** keep checked named carriers and `floating_domain`; no facet
   duplication, unchecked conversion to constrained names or assertion-policy
   dependence. Public generated `Encode_*` / `Decode_*` signatures stay compatible.
6. **Generator design:** explicit decoder **and emitter** contexts; helper demand
   derives from semantic emitted primitive use, never schema-name substrings or
   generated-text replacement. Preserve existing portable/Float32-only output;
   broaden only the tested composition shapes. Keep internal defects visible,
   validation as Codec_Error, unsupported environment/resource distinct.
7. **Atomicity:** build temporary typed models/output buffers and publish after
   validation. Handle bounds/cardinality at precise field/index scope. Resource
   failure must never be disguised as valid JSON or numerical success.
8. **Deployment/tests:** source-pinned dependencies, compiler/link flags and C
   bridge packaging must be documented. Add production generator unit/golden,
   negative readiness, identifier collision, nested/repeated/Choice, special,
   Unicode/limits, locale/resource and independent environment controls; execute
   the exact oracle and complete output path on hosted exact-head targets.
9. **PR #94:** combine only after its merge, preserving semantic helper demand,
   hexBinary conventions and failure atomicity; requalify affected mixed paths.
   Nothing here changes that branch, its CI or metadata.

Prior UCI findings motivate this boundary but do not establish service readiness.
Neither ScanDataBaseType nor any whole service automatically becomes READY.
This is deterministic sampled qualification, **not an exhaustive proof across
all 2^64 encodings** or a guarantee about NaN payload/signaling preservation.
