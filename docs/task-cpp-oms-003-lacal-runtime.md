# CPP-OMS-003 — C++17 LA-CAL WebSocket runtime and authentic UCI `Log` interoperability

Builds on CPP-OMS-002 (PR #168, branch head `8099fcb8…`, unmerged when this
work started; this branch is stacked on it). Adds a separately maintained,
handwritten C++17 LA-CAL runtime under `cpp/oms-lacal-runtime/` that the
**existing, unchanged** generated `service_api.hpp` forwards to, with payload
bodies encoded and decoded only by the **existing, unchanged** generated
`service_codec.hpp`. No generator source, generated byte, Sleet source or wire
rule changed.

```text
generated service_api.hpp     exchange_publish::publish(runtime, value)
        |                     exchange_receive::subscribe(runtime, handler)
        v  (duck-typed adapter hooks, Task 048)
ams_gra::lacal::Runtime       cpp/oms-lacal-runtime  (handwritten, this task)
        |  payload_codec<P> -> generated service_codec::encode_P / decode_P
        |  global-element envelope, OWP 1.0 framing, SIDs, dispatch, lifecycle
        v
Boost.Beast WebSocket         Sec-WebSocket-Protocol: owp, ws:// only
        v
Sleet e38f61d8 (unmodified) or any LA-CAL server
```

## 1. WebSocket dependency decision

Implementing RFC 6455 framing or the opening handshake was out of scope by
requirement, so a library was selected.

| Candidate | License | Assessment |
| --- | --- | --- |
| **Boost.Beast** (Boost 1.83) | BSL-1.0 | **Selected.** In Boost since 1.66 (2017), actively maintained, header-only over Boost.Asio (no Boost library is linked; only `-pthread`). Client handshake with a request decorator for `Sec-WebSocket-Protocol`, access to the upgrade response (so the selected subprotocol is checked), `read_message_max`, automatic ping/pong while a read is pending, UTF-8 validation of text messages, and async operations that let one thread own the socket. |
| websocketpp 0.8.2 | BSD-3-Clause | Last release 2020; does not build against current standalone Asio (removed `io_service`) without patches. Rejected. |
| IXWebSocket | BSD-3-Clause | Owns its own background threads and callback delivery; that would put callback/lock ownership outside this runtime's control. Would also need a fetched, built git pin. Rejected. |
| libwebsockets | MIT | C event-loop library with a large build/configuration surface (CMake, TLS options) for a small client role. Rejected. |
| uWebSockets | Apache-2.0 | Server-oriented. Rejected. |

**Reproducibility.** The runtime `static_assert`s `BOOST_VERSION >= 108100` and
was qualified on **Boost 1.83.0** from the Ubuntu 24.04 archive
(`libboost1.83-dev 1.83.0-2.1ubuntu3.2`, `libboost-dev 1.83.0.1ubuntu2`;
`BOOST_BEAST_VERSION` 347). The qualification scripts print the exact version
they compiled against. PR smoke installs the same Ubuntu package
(`libboost-dev`) on its existing `ubuntu-24.04` runner. BSL-1.0 is permissive
and compatible with this repository's Apache-2.0 licence; nothing is vendored.

## 2. Public API (`include/ams_gra/lacal/runtime.hpp`)

```cpp
// once per payload type, at global scope: bind to the GENERATED codec
AMS_GRA_LACAL_PAYLOAD_CODEC(::programs::oam::LogMT,
                            ::service_codec::encode_LogMT, ::service_codec::decode_LogMT)

ams_gra::lacal::Config config;
config.url = "ws://127.0.0.1:4222";          // wss:// is refused (unsupported_scheme)
config.service_id = "task102-log";
config.schema_version = "002.5.0";           // required; never defaulted
auto runtime = ams_gra::lacal::Runtime::connect(config);           // Result<Runtime>

auto sub = log::exchange_receive::subscribe(*runtime, [](const LogMT& v) { ... });  // Result<Subscription>
ams_gra::lacal::Status s = log::exchange_publish::publish(*runtime, value);        // Status
s = sub->unsubscribe();
while (auto event = runtime->poll_event(std::chrono::milliseconds(0))) { ... }
runtime->close();
```

| Item | Contract |
| --- | --- |
| `Runtime::connect(Config)` | TCP + WebSocket upgrade offering `owp`; the response **must** select exactly `owp`; then `INIT {"versions":["1.0"],"schema":…,"verbose":true,"service_id":…}`, `+OK`, and a valid `INFO` (object, offered `version`, string `server_id`), all within `connect_timeout`. |
| `publish<P>(ns, name, topic, value)` | generated-facade hook. Generated encoder → `{"<element>":body}` → `PUB`. Returns after the peer's `+OK`/`-ERR`. |
| `subscribe<P,H>(ns, name, topic, group, handler)` | generated-facade hook. Allocates `sub-N`, sends `SUB`, activates dispatch on the `+OK` (on the I/O thread, before any later frame is read). Returns a move-only `Subscription`. |
| `Subscription::unsubscribe()` | one-shot; removes local dispatch first, waits for an in-flight handler (unless called from it), sends `UNSUB`, returns its acknowledgment. Destroying an active handle does the same (outcome not reported). |
| `poll_event(timeout)` | asynchronous `Event`s: `server_error`, `decode_error`, `unknown_subscription`, `handler_exception`, `info`, `connection_closed`, `events_dropped`. |
| `close()` / `~Runtime` | WebSocket close (bounded by `close_timeout`), dispatcher stopped after the running handler returns, both threads joined, every Asio object destroyed. Idempotent. Refused inside a handler. |
| `stats()` | `delivered`, `decode_errors`, `unknown_subscription`, `handler_exceptions`, `discarded_on_close`, `events_dropped`. |

`ErrorKind` separates every failure class: `invalid_argument` (config,
non-identifier topic/group/service ID, unrepresentable QName — no frame sent),
`unsupported_scheme`, **`codec`** (generated encoder rejected the value — nothing
sent; `codec_path` from the generated codec), `connect_failed`,
`handshake_rejected` (HTTP non-101 or wrong/missing subprotocol), **`broker_rejected`**
(`-ERR` for this operation; `owp_code`/`owp_details`), `protocol_violation`,
`timeout`, `connection_closed`, `subscription_inactive`,
`subscription_ids_exhausted`, `delivery_overflow`, `called_from_runtime_thread`.

`owp.hpp` exposes the pure framing layer (identifier grammar, the single
LA-CAL name formatter, frame builders, server-frame parser, envelope unwrap,
INFO check) for testing without a network.

## 3. Preserved OMS/OWP architecture

* Subprotocol `owp`; OWP version `1.0` only (others rejected locally).
* One LA-CAL name formatter: the bare local name for exactly
  `https://www.vdl.afrl.af.mil/programs/oam`, `{namespace}local` otherwise. It
  produces the published member, the expected received member and the SUB
  name. The UCI message is **`Log`**, never `LogMT` (asserted against the
  generated constants and on the wire).
* `PUB <topic> {"<element>":<body>}` — exactly one member (§6.1.1); the body is
  the generated codec's text, unchanged.
* `MSG` dispatch by SID only. The envelope must be one object with exactly one
  member equal (after unescaping) to the subscribed element; its exact source
  text is passed to the generated decoder.
* Frame grammar mirrors the spec and the pinned Sleet parser: single-space
  outgoing separators, SPACE/TAB-run incoming separators, case-sensitive
  keywords, known `-ERR` codes only. No operation, field or acknowledgment was
  invented.

## 4. Runtime safety design

| Concern | Mechanism |
| --- | --- |
| Socket ownership | One I/O thread runs a private `io_context` and owns the WebSocket, resolver, timers, buffers and write queue. Other threads only `post`, always under the state lock while the state is active, so `close()` can never race a post. |
| Callbacks and locks | A separate dispatcher thread decodes and runs handlers with **no runtime lock held**. Internal bookkeeping (SUB activation) never calls user code. Handler destructors run outside locks. Handlers may publish, subscribe and unsubscribe (including their own subscription); `close()` from a handler returns `called_from_runtime_thread`. |
| Real acknowledgments | Verbose OWP and a bounded command slot: exactly one command awaits `+OK`/`-ERR`, so each status is paired with its command (Sleet replies in order per connection). An unpaired `-ERR` is a `server_error` event; an unpaired `+OK` is a protocol violation. Success is never reported for an unacknowledged frame. |
| Bounded waits | `connect_timeout`, `operation_timeout` (slot wait and ack wait), `close_timeout`; joins are bounded by forcing the `io_context` to stop. A missing ack **fails the connection** (a late ack could otherwise be mis-paired). |
| Subscription ownership | Move-only RAII handle holding a `weak_ptr` to the core: it may outlive the `Runtime` safely. IDs `sub-1, sub-2, …` are never reused (also consumed by locally rejected SUBs); 64-bit exhaustion fails closed. |
| Shutdown | No detached threads. `close()` joins both threads and destroys all Asio objects, which also joins Asio's internal resolver thread (IP literals skip DNS entirely). Destroying the core with running threads terminates loudly instead of risking use-after-free. |
| Connection loss | Transport errors, peer close frames, oversized frames, binary frames and invalid OWP frames end the connection explicitly (`connection_closed` event with the reason; the outstanding command fails immediately). MSGs already received are still delivered. No reconnect. |
| Malformed payloads | Envelope or generated-codec rejection is a `decode_error` event (with codec path and raw payload); the subscription stays active and other subscriptions are unaffected. Handler exceptions are contained. |
| No silent loss | Bounded MSG backlog (`max_pending_deliveries`); overflow closes the connection with `delivery_overflow` rather than dropping. Events beyond `max_pending_events` are counted and reported as `events_dropped`. MSGs queued at `close()` are counted in `discarded_on_close`. |
| TLS | Not implemented; `wss://` is refused explicitly before any network activity. Only loopback `ws://` is qualified. |

changed to a mutex/condition variable so TSan models it fully, rather than
suppressing the report.

## 7. Limitations (not claimed)

* No TLS (`wss://` refused), authentication, reconnect, resubscribe or
  backoff. Only loopback `ws://` is qualified.
* Pairing of `+OK`/`-ERR` relies on the peer answering each command in order,
  which OWP `-ERR` (no operation/SID field) cannot prove; the pinned Sleet
  does so. An unsolicited `-ERR` that arrived exactly while a command was
  outstanding would be attributed to that command.
* One outstanding command per connection (throughput is bounded by the
  round-trip time); handlers run on one dispatcher thread, serially.
* `unsubscribe()` waits at most `operation_timeout` for a running handler,
  then reports `timeout`. `close()` waits for a running handler without bound.
* Only the authentic `Log` message is qualified against Sleet; other UCI
  messages depend on C++ codec readiness (CPP-OMS-002 limits).
* clang++ sanitizers were not exercised in this environment. Hosted PR smoke
  runs strict g++ only.
